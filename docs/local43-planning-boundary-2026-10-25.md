# local.43 规划层加速与执行边界

## 改动边界

```text
实时网络快照（原服务端逻辑）
  -> 当前样板与替代槽解析（原逻辑，仍每请求进行）
  -> 冻结数值规则 / 数值编译缓存（新增）
  -> 选择无环供料路线、合并共享需求后批量取整（新增）
  -> 原前缀资本与前向执行认证（不绕过）
  -> 当前请求重新绑定 PatternVariant / IPatternDetails（原逻辑）
  -> 原 CPU 顺序派发 / waitingFor / 回料 / 交付（不改）
```

这不是把已安装物理样板重新编码，也不是替换执行中的程序。新的缓存不含任何游戏对象、物品键对象、当前库存、槽分配、计划、CPU 或游标。数字位置随请求映射到当前物理对象；同一数值规则但不同槽布局只能复用数值编译，不能复用旧槽位。

不改动 `CertifiedCraftingPlan`、`ProductionJob`、`ProductionCursor`、原生/AdvancedAE CPU Mixins、NeoECO 外部批量旁路隔离或 NBT 程序格式。旧订单仍执行它已提交的程序。若玩家实际移除正在使用的物理样板，供应器下线仍按原本机制处理，不用新编译的替代样板偷偷接管旧订单。

## 缓存不变量

- 完整输入/输出数量图与规则顺序比较，不只比较哈希；返回物属于输出图，改变返回物会失效。
- 不把目标、订单数量或库存作为编译内容；每次重新计算需求和检查种子，不能把缺料变成有料。
- 操作数合法性在命中之前检查，防止重复键被 Map 合并后伪装成合法缓存项。
- 最多 32 项、262144 权重单位、60 秒 TTL；权重不是字节数。只在短暂 get/put 时持锁，不在全量编译或搜索期间持锁。
- 编译超时不缓存半成品，取消不共享 Future，不连带取消别人的请求；停服清理数值与精确计划缓存。

## 聚合算法

先按库存可达层次排序候选正净产出配方，再用有界的无环路线选择避免把升降级转换环当作无限递归。无生产者但有真实库存的材料可作为供料叶子。对于选定路线，建立配方级依赖 DAG，每个共享生产者等所有父节点传播需求后，统一扣除库存、按产出批量向上取整。催化剂或返还资本独立保留，不乘以整批执行次数。

只有选定路线的聚合是按图规模处理；路线选择不是完备可行性判定。复杂反馈环、有限库存混用替代路线、需要先制造的启动种子等不适用时，仍可进入原循环探测与通用反向搜索。候选证明失败也是回退，不能记为缺料或污染原始库存。所有快路径共用原预算，不增加总时限或搜索状态上限。

证明成功后返回的仍是原批量执行程序。目标已有库存不能算作本次净新增；中间物、返回物、累计次数与原生计数器的有符号 long 容量仍校验，不饱和、不截断。

## 回归范围

- 30 万 / 10 亿顶层数量的带返回催化剂四级升降级图：DAG 命中、4 个程序块，检查精确原料及次数。
- 多父共享子配方需求合并后才取整、库存只扣一次，同一配方多产物只批量执行一次。
- 46 层斐波那契共享依赖、已有目标库存、启动资本、真正增殖环回退、long 容量与不足原料。
- 80 个随机共享 DAG，从实际提取的资本逐次物理重放，检查每次执行前材料足够。
- 编译缓存的数量/返回物/顺序/键映射失效、源数组修改、取消、并发、上限与停服。
- 同流不同槽位的重新编译绑定，以及同时存在旧活跃程序与新请求时，旧槽位、旧资本和旧游标不改变。
- 保留 local.42 的 NeoECO 旁路隔离测试，并在实际加载 NeoECO 的独立服务器执行取消、重载、恢复等场景。

最终 `test` 与启用 `-Xverify:all` 的 `routeFunctionalTest` 各 52 套、387 项，失败 0、错误 0；两者运行的是同一批回归，不算 774 个不同测试。原始记录在 `logs/local43-final-build.log`。

实际加载 NeoECO、Thunderbolt 与 AdvancedAE 的 8 个独立服务器场景全部通过：`growth`、`cancel`、`reload`、`advanced`、`partial`、`paths`、`restart1`、`restart2`（18:36–18:44）。覆盖循环回料、取消不交付、CPU NBT 重载、量子 CPU、部分交付重试、画布选择及跨进程恢复；NeoECO 场景还记录旁路在访问认证任务前被隔离。日志为 `logs/local43-selftest-<task>.log`。

最终未安装 NeoECO 的独立 `growth` 场景也通过（18:46），验证可选兼容与规划器不依赖该模组。主存档和游戏 `mods` 均未改动。

## 性能证据边界

使用同一 Java 21、512 MB 堆、30000 状态和 5 秒预算，将 local.42 提交 `d5515b1` 的规划器与本轮实现进行独立 JVM 单次诊断。编译输出在忽略目录 `build/diagnostics/local43-comparison/`，不修改游戏或主存档。

初轮单样本（含构造，首条含冷启动/JIT）中，旧规划器的 46 层共享图耗尽约 5 秒预算，新路径在约 20 ms 得到 47 块认证程序；四级 30 万/10 亿图两版均可行，新路径不需状态搜索。它们不是稳定性能统计，也不是玩家真实精华网络的导出；不能据此保证实际订单延迟或所有网络不超时。

完整 ATM10 的原 30 万精华订单仍需在新包上单独复测。大数量可计算也不代表 CPU 存储或机器吞吐足够；本轮不改原生 bytes / long 接口上限。
