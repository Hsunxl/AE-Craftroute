# local.45：区分大数量计算与资源不足

## 现场与复现边界

local.44 实际日志：`mysticalagriculture:imperium_essence` 的 10000 请求约 85 ms 成功；30000 / 300000 请求约 5 秒后在 worker computation 耗尽预算。不是 long 溢出，也不是服务器线程快照采集慢。

只读检查存档中已编码的升级样板，以及存储元件中的混合库存，抽象为匿名 e0..e5 和返回工具。没有修改主存档。库存快照 e0=501410、e1=136039、e2=875、e3=968，工具=25。每级 4:1 升级，工具原样返还；工具自身可用更高阶精华制造，产生额外图环。

仅这条已编码升级链能净增 e3 的上界为：

```text
floor((floor((floor(501410 / 4) + 136039) / 4) + 875) / 4) = 16555
```

原有 e3 不是本次新增产物，不能用于冒充订单完成。此快照不等同于完整运行时网格：外部存储、动态 EMC 转换、远端提供器和实时库存变化仍以游戏内快照为准。不会在代码里硬编码这些数量或物品。

## 通用证明

设非负权重为 w。只有精确确认每条已枚举物理转换满足 `w·outputs <= w·inputs`，且 `w·stock < w[target] * (stock[target] + requestedIncrement)`，才可断言目标无法达到。该判定考虑所有候选生产者，不是只检查启发式选中的路线。种子/容器返回通过真实净变化抵消，而不是假定某件工具免费。

构造器只是有界启发式：256-bit 初始精度，整数向上取整，最终逐规则重新验证。量化误差只会削弱候选上界；没有浮点误差参与缺料判断。未收敛、自由产出或正增长环使证明失效时返回未知，继续原规划；取消向上传播。独立阶段最多 50 ms，且始终受原请求剩余预算限制。不增加原来的 5 秒预算。

仅给结果增加可选上界元数据，旧构造接口仍可用；执行桥、计划证明、游标、回料和 NBT 格式均未改动。未穷尽的替代输入仍先报告不支持，不能以这个已枚举子图的证书冒充全局缺料证明。

## 数量上限补充

用户询问上游的 10^12 数量级后，另用当前已构建规划器执行足量原料的三层 4:1 升级测试：10^12 目标为 FEASIBLE / 3 个程序块 / 原料 64×10^12，单次约 54.7 ms；10^15 目标同样 FEASIBLE / 3 块，热身后单次约 4.96 ms。纯数值 1:1 配方的 Long.MAX_VALUE 净增目标也通过。此项只运行数值规划及其内置认证，不代表游戏执行了万亿次配方，也不证明任意复杂图都能在预算内求解。

接口数量与任务计数为 long（最大 9223372036854775807），规划需求/前缀/守恒势能使用 BigInteger。实际绑定还要核验全部计数乘法、产物追踪计数、中间库存以及计划字节数不溢出，CPU 也必须有足够合成存储。因此单订单没有一个对所有配方均适用的“保证可合成数量”。例如这里的计划字节数按各样板执行次数 × (输入槽数 + 1) 累加，不能把纯数值 Long.MAX_VALUE 边界当成 AE2 可提交上限。
